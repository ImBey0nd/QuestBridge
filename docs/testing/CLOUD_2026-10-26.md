## Reproduction and environment fixes

Read [Android build instructions](../../headset/android-openxr/README.md). Tools and their observed versions are recorded in [toolchain.txt](evidence/cloud-2026-10-26/toolchain.txt); [manifest.json](evidence/cloud-2026-10-26/manifest.json) records bootstrap, loader AAR, plugin and APK hashes. The host CMake was installed from the public `cmake==3.31.6` PyPI wheel into `/workspace/.tool-packages`. The Android toolchain is under `/workspace/android-sdk`, JDK/Gradle under `/workspace/toolchains`; all are outside Git.

In this retained cloud environment:

```sh
source /workspace/questbridge-cloud-env.sh
cd /workspace/QuestBridge
npm test
cmake -S . -B build-cloud
cmake --build build-cloud
ctest --test-dir build-cloud --output-on-failure
node tools/diagnostics/cross-language.mjs build-cloud/qb_native_tests
node tools/diagnostics/validate.mjs
npm run demo
tools/build/android.sh clean
"$ANDROID_HOME/build-tools/34.0.0/apksigner" verify --verbose \
  artifacts/cloud-2026-10-26/questbridge-probe-debug.apk
```

This environment requires the execution tool's network permission for local UDP sockets and outbound downloads. The first Node attempt failed with `bind EPERM`; with network permission, the unchanged tests passed. CMake was initially absent. SDK manager initially could not write its cache under `/home/agent`; `ANDROID_USER_HOME` selects a writable directory. Gradle/Java use the configured proxy explicitly and retain TLS verification with the system Java trust store. A writable Java `user.home` removes the build analytics-settings warning. None of these failures required changing the protocol or weakening its checks.

The uploaded repository contained tracked Windows CMake outputs and lacked `.gitignore`, a Gradle wrapper and CI workflow. Generated Windows outputs were removed from Git. The final changes add appropriate ignores, a checksummed Gradle wrapper, build helper, explicit plugin-default Build Tools 34.0.0, target SDK 35, packaged license notices and CI. Shared runtime/protocol implementations are unchanged.
