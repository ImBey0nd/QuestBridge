# Experimental wire protocol v1
UDP datagrams, maximum 1200 bytes, big endian. Protocol is experimental and not interoperable with ALVR.
Header: magic QBRG (4), version u16 (1), type u16, payload bytes u16, reserved u16 (0), session u64, sequence u64, sender monotonic microseconds u64, reserved u32 (0). Total 40 bytes.
Payload follows. Final 32 bytes are HMAC-SHA256 over header and payload, using a privately exchanged 32-byte random key.
No encryption, forward secrecy or interactive pairing UI. Initial key exchange is manual out of band. Use private trusted networks. No unauthenticated input updates state.

Types: HELLO=1, WELCOME=2, TRACKING=3, PING=4, PONG=5, VIDEO=6.
HELLO: session zero, 16 random nonce bytes. Host supports one active peer bound to IP, UDP port and random nonzero 64-bit session.
WELCOME: assigned session and echoed nonce. Client accepts only while connecting, with its current nonce.
The version must exactly match; no older version fallback. This is version acceptance, not codec/refresh/capability negotiation.
Established packets require increasing sequence. Duplicates/out-of-order packets are dropped. Gaps count missing sequence numbers, not proven network loss.
Client sends tracking at nominal 90Hz and PING at 4Hz. Host expires peers after 2s by default; client reconnects after 1.5s without PONG. HELLO retries share one nonce until session establishment.
Host validates message direction and semantics before advancing accepted sequence.
HELLO replay can temporarily occupy an idle receiver for its timeout: this prototype has no replay cache for prior handshakes or denial-of-service protection. It is not a hardened transport.

TRACKING: exactly 156 bytes, head/left/right records of 52 bytes.
Each record: 11 IEEE754 float32 values (position xyz meters, quaternion xyzw, stick xy, trigger, grip), buttons u32, flags u32.
Right-handed +Y up, -Z forward. Quaternions approximately normalized (squared norm within 0.02).
Flags bits 0..3: position valid, orientation valid, position tracked, orientation tracked. Untracked data remains finite and should be ignored by consumers according to flags.
Buttons bits 0..7: primary, secondary, menu, stick click, trigger click, grip click, primary touch, secondary touch. These are generic logical slots, not verified PS VR2 mappings.
Position limited to +/-1000 meters. Sticks [-1,1], trigger/grip [0,1]. Unknown bits and nonfinite values rejected.

PING: t0 u64. PONG: t0,t1,t2 u64 (client send, host receive-handler timestamp, host send timestamp).
Client t3=receive time. RTT=(t3-t0)-(t2-t1); host-minus-client offset=((t1-t0)+(t2-t3))/2.
Scheduling and path asymmetry affect estimates. No one-way latency or motion-to-photon measurement is claimed. XrTime is not directly interchangeable with this clock.

VIDEO: fixed diagnostic format only: 24 bytes = left then right eye, each 2x2 RGB8. Header sequence is frame ordering and header time is packet creation time, not capture/presentation time.
No fragmentation, compression, rendering, resolution negotiation or hardware acceleration is implemented in UDP v1.
Native FrameAssembler is an independently tested utility for a future transport. It is not connected to UDP v1.

Before a deployable transport: audited crypto on native clients, per-session keys/challenge replay protection, explicit capability/format negotiation, deadlines, tracking age checks, session rate limits, video frame IDs and timestamps, congestion control, and clock-domain integration.
