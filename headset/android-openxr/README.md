# Android/OpenXR runtime probe

Status: **debug APK compiled, linked, packaged, signature checked and linted in Linux cloud on 2026-10-26**. No headset installation or execution has been performed.

This regular Android Activity calls JNI to initialize the Khronos loader, create an OpenXR instance, ask for an HMD system and destroy the instance. It does not create an XR session, graphics binding, tracking actions, renderer, network connection or video decoder. Its on-screen result and `QuestBridge` logcat tag are the evidence needed for the next device experiment.

## Build

Use JDK 17, Android command-line tools and these SDK packages:

```sh
sdkmanager --licenses
sdkmanager 'platforms;android-35' 'build-tools;34.0.0' 'ndk;27.2.12479018' 'cmake;3.22.1' 'platform-tools'
export JAVA_HOME=/path/to/jdk-17
export ANDROID_HOME=/path/to/android-sdk
# From the repository root:
tools/build/android.sh
# To rebuild from clean outputs:
tools/build/android.sh clean
```

SDK license acceptance is required for installation. The checked-in Gradle wrapper downloads Gradle 8.9 and verifies its official SHA256. It was generated by the verified Gradle 8.9 distribution; its JAR hash also matches the official checksum. Android Gradle Plugin 8.7.3 and Khronos loader 1.1.65 remain pinned. Build Tools 34.0.0 is the plugin's observed default, now explicit. No global Gradle installation is needed. Windows users can invoke `gradlew.bat :app:assembleDebug :app:lintDebug` inside this directory.

Output: `app/build/outputs/apk/debug/app-debug.apk` (debug signed, ARM64 only). Lint reports: `app/build/reports/lint-results-debug.{txt,html,xml}`.

The probe now targets SDK 35, fixing lint's expired-target error in the original SDK 32 scaffold. `minSdk 29` is unchanged; targeting 35 does not require Android 15 for installation, but OS/runtime behavior still requires device testing. This diagnostic APK is not store certified. Five lint warnings remain: fixed landscape orientation, no ChromeOS x86 ABI, backup-extraction rules, missing launcher icon and hardcoded UI text. They do not block the build and are retained in the evidence.

The loader AAR's manifest supplies the OpenXR permissions and runtime-broker/service queries; their presence was checked in the packaged manifest. The APK contains `libopenxr_loader.so` and `libquestbridge_probe.so`. Third-party notices and license texts are packaged in `assets/`.

## Managed cloud setup

All tools for the recorded run live under `/workspace`; the owner's PC was not used. In this existing cloud workspace:

```sh
source /workspace/questbridge-cloud-env.sh
tools/build/android.sh clean
```

That untracked environment file selects JDK, SDK, writable Android/Gradle/Java homes, the session proxy and the system Java trust store. On a fresh cloud environment recreate those locations with the tool versions below. Java SDK tools and Gradle need explicit proxy settings when outbound networking requires the session proxy; merely inheriting `HTTPS_PROXY` is insufficient. Keep certificate verification enabled. Do not commit proxy credentials, debug keystores or machine-specific `local.properties`.
